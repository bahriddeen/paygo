# Building the Windows installer

Produces `release/Qarz Daftari-<version>-x64-setup.exe` (NSIS, x64).

## Prerequisites (once)

Generate the license signing keypair, which also writes the embedded public key
the app builds against:

```bash
npm run license:keygen
```

- Private key → `tools/license-gen/keys/private.pem` (git-ignored — **keep it
  secret and backed up**; it signs every activation code).
- Public key → `src/main/license/publicKey.ts` (committed; shipped in the app).

Mint activation codes anytime with `npm run mint -- 100 > codes.txt`.

## Recommended: build on Windows / CI

The reliable path — no Wine, no cross-compile surprises, and it can code-sign
natively.

- **GitHub Actions:** push a tag `vX.Y.Z` (or run the workflow manually). See
  `.github/workflows/build-win.yml`; the installer is uploaded as an artifact.
- **A Windows machine:** `npm ci && npm run build:win`.

## Cross-building from macOS (Apple Silicon)

Works, but needs Wine for the NSIS/exe steps:

```bash
brew install --cask wine-stable
npm run build:win        # electron-vite build + electron-builder --win --x64
```

`--x64` is set both on the CLI and in `electron-builder.yml` (`arch: [x64]`) so an
arm64 Windows build is never produced by accident on an M-series Mac.

## Notes

- **No native modules** — `node:sqlite` is built into Electron and `exceljs` is
  pure JS, so there's no `electron-rebuild` step (`npmRebuild: false`).
- **Code signing:** unsigned installers trigger a SmartScreen "unknown publisher"
  warning. To sign, add a Windows code-signing certificate (env vars
  `CSC_LINK` + `CSC_KEY_PASSWORD`); signing is easiest on the Windows/CI path.
- The app icon is generated by `node tools/icon/generate-icon.mjs` → `build/icon.png`.
